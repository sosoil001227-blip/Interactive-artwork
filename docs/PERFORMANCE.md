# 최적화와 배포

예제 8·9의 손 인식 모델, 카메라 목표 해상도(1280×720), Canvas 픽셀 비율 상한, 물결 시뮬레이션 해상도와 셰이더, 마법진·입자 구성은 유지합니다. 모델이나 폰트의 손실 압축, 효과 제거, 저화질 전환은 적용하지 않습니다.

## 실행 중 작업량

- MediaPipe의 동기 손 인식을 별도 classic Worker에서 처리합니다. 지원하지 않는 환경이나 Worker 오류 시 메인 스레드로 전환하고, 모델의 GPU 초기화 실패 시 CPU를 사용합니다.
- 카메라의 새 프레임만 최대 30회/초 처리하고, 추론 중에는 다음 프레임을 추가하지 않습니다. 완료된 지 오래된 요청이나 화면 전환·초기화 이전 요청의 결과는 무시합니다.
- 90/120/144/240Hz 디스플레이에서도 렌더링을 최대 60회/초 수행합니다. 물결 시뮬레이션은 기존 60Hz를 유지합니다.
- 숨겨진 탭에서는 animation frame 예약을 취소하고 영상 재생·카메라 트랙 입력·오디오를 일시 중지합니다. 트랙은 다시 켜기 위해 보유하며, 실제 카메라 하드웨어의 대기 동작은 브라우저에 따라 다릅니다. 카메라 끄기와 페이지 이동 시에는 트랙과 인식 자원을 종료합니다.
- 물결의 uniform 배열과 카메라 텍스처를 재사용합니다. 손끝 캔버스는 표시가 바뀔 때만 다시 그립니다. 마법진 입자·발사체는 새 배열을 매 프레임 만들지 않고 정리합니다.
- 오디오의 동일한 값은 반복 예약하지 않고, 새 값으로 전환할 때 이전 자동화를 정리합니다. 소리 OFF와 카메라 종료 시 오디오 컨텍스트를 일시 중지합니다.

Worker는 설치 시와 프로덕션 빌드 시 `public/workers/hand-worker.js`로 생성합니다. 개발 모드에서도 같은 classic Worker를 제공하여 MediaPipe의 `importScripts` 로더가 동작하도록 합니다. Worker 관련 소스를 변경했다면 `npm run build:worker`로 재생성하세요.

## 무손실 전송 압축

`npm run build`는 `dist/`에 원본 파일을 보존하고 HTML·CSS·JS·SVG·WASM·손 인식 모델의 `.br`·`.gz` 파일을 추가합니다. WOFF2 폰트는 이미 압축되어 있어 다시 압축하지 않습니다. 압축 파일이 더 큰 경우에는 생성하지 않습니다. 의존성이나 외부 압축 서비스는 추가하지 않습니다.

2026-11-19 빌드의 압축 대상 합계는 약 38.21MB이며, Brotli는 약 12.64MB(약 67% 감소), gzip은 약 14.42MB입니다. 이 수치는 두 예제와 두 WASM 변형을 포함한 압축 대상 전체의 합계이며, 한 번 방문할 때 실제 내려받는 용량과는 다릅니다. 원본과 압축본을 함께 보관하므로 배포 폴더의 디스크 용량은 증가합니다.

배포 서버는 아래 조건을 충족해야 합니다.

1. 요청 URL은 원래 이름을 유지합니다. 클라이언트의 `Accept-Encoding`에 따라 대응하는 `.br` 또는 `.gz` 파일을 제공하고, 지원하지 않으면 원본을 제공합니다.
2. 압축 파일을 제공할 때 `Content-Encoding: br` 또는 `gzip`, `Vary: Accept-Encoding`을 설정합니다. `Content-Type`은 원본에 맞춰 유지합니다. WASM은 `application/wasm`, Worker와 JavaScript는 JavaScript MIME 타입으로 제공해야 합니다.
3. 파일명에 해시가 있는 `assets/`만 장기 immutable 캐시를 적용합니다. HTML, 고정 경로의 `workers/hand-worker.js`, 모델·WASM에는 재검증 가능한 캐시 정책을 사용합니다.

Nginx의 `gzip_static`이나 Brotli 모듈의 `brotli_static` 기능, 호스팅 서비스의 사전 압축 지원을 사용할 수 있습니다. 설치된 서버 모듈과 호스팅 설정에 맞춰 적용해야 합니다. 개발 서버는 원본 파일을 제공하므로 전송 압축 결과는 배포 빌드에 해당합니다.

## 검증과 지원 범위

개발·미리보기 서버를 실행하지 않고 `npm test`와 `npm run build`로 검사합니다. 테스트는 기존 손 인식·제스처 검증, 프레임 제한과 백그라운드 복귀, Worker의 취소·자원 해제·폴백, 오디오 자동화, 텍스트·바이너리 압축 복원을 포함합니다.

JavaScript 문법은 Chrome/Edge 79, Firefox 78, Safari 14 대상으로 변환합니다. 이는 문법 변환 기준이며 해당 버전 전체에서 실행 가능하다는 보장은 아닙니다. 실제 동작에는 카메라 권한, 보안 컨텍스트(HTTPS 또는 localhost), 모델 런타임에 필요한 WebAssembly와 그래픽 기능이 필요합니다. 예제 8은 WebGL2와 부동소수점 렌더 타깃을 사용합니다. 인앱 브라우저가 카메라·Worker·그래픽 기능을 차단하거나 운영체제가 자원을 제한하는 경우 웹 코드로 그 제약을 해제할 수 없습니다.

실기기별 프레임 시간·온도 측정과 모든 운영체제·인앱 브라우저의 검증은 수행하지 않았습니다. 모든 환경의 무발열·무끊김을 보장하는 결과로 해석하면 안 됩니다.
